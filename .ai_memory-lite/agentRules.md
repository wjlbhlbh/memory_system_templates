# AI 行为规则 (Agent Rules)

## 1. 初始化协议
- 所有新会话必须先完整读取 `.ai_memory` 下所有 Markdown
- 读取顺序以 `index.json` 的 `bootstrap_order` 为准
- 未完成初始化前，不允许输出计划结论或开始修改文件

## 2. 证据与分级协议
- 遇到不确定事实时，必须先验证再下结论。
- 输出结论时至少区分：已确认事实、基于事实的推断、仍待确认的问题。
- 开始执行前先做任务分级：L0 可直接做并最小验证，L1 先说方案再做，L2/L3 必须先确认。
- 涉及数据库、认证、支付、权限、公共 API、部署、环境配置、不可逆操作时，默认按高风险处理。

## 3. 编辑纪律
- 修改前必须重新读取目标文件最新快照。
- 禁止基于旧记忆直接套用 Search/Replace。
- 禁止为了“省事”重写整个文件，除非用户明确要求。
- 优先做最小必要改动，避免顺手大范围重构。
- 禁止无说明地删除历史、覆盖已有真实改动或引入不必要的新依赖。

## 4. 验证与完成协议
- 未执行真实命令验证前，禁止标记 `[DONE]`。
- 仅代码通过但前端未验收时，状态只能是 `[AWAITING_QA]`。
- 如果修复失败并发现原方案错误，应标记 `[REWORK]`。
- 没有验证，就不算完成；不能用“应该没问题”代替验证结果。

## 5. 记录协议
- 每完成一个独立子任务，向 `progress.md` 追加一条记录。
- 当前状态变化必须同步到 `activeContext.md`。
- 不删除真实历史，只允许补充、折叠、迁移。

## 6. 一口气交付协议
- 默认以“减少打扰优先”执行：小决策由 AI 基于现有文件、仓库约定和工程常识保守判断，不反复询问用户。
- 标准流程：先读 `.ai_memory` 与相关文件，再实施、补必要测试或验证、更新 `progress.md`，最后总结改动、验证、产品判断和剩余人工事项。
- 只有遇到缺少密钥、外部平台权限、必须人工扫码/发布、生产不可逆操作、需求真实冲突等硬性阻塞，才暂停询问。
- 严禁为当前任务破坏无关模块、页面、接口或已有流程；无法确认影响面时先缩小改动。

## 7. 源码提交与本地备份分层协议
- 任务完成并验证后，默认自动执行 `git status` -> `git add` -> `git commit -m "中文提交名"` -> `git push`。
- 提交名尽量使用中文，说明真实改动，不写空泛的 “update”。
- 正常源码、文档、测试、配置进入 Git；本地备份统一放 `.archive/`，并把 `.archive/` 写入 `.gitignore`。
- 本地数据库、日志、缓存、临时目录、运行产物必须写入 `.gitignore`；若已被 Git 跟踪，用 `git rm --cached` 取消跟踪并保留本地文件。
- 完成后确认 `git status --short` 为空；若不是 Git 仓库、无远程、无权限或网络失败，如实说明阻塞。

## 8. 文件编码与完整性协议
- Agent 可读文件默认使用 UTF-8 无 BOM，尤其是 `.md`、`.json`、`.yaml`、`.yml`、`.txt`、工具入口模板。
- 写文件必须显式指定编码，禁止依赖系统默认编码。
- 文件乱码、编码异常、JSON 解析失败应视为记忆系统故障，先修复可读性再继续工作。
- 修改记忆系统后至少检查关键文件可读、`index.json` 可解析、`bootstrap_order` 不引用缺失文件。
