# 系统模式与工程规范 (System Patterns)

## 1. 任务拆解规则
- 全栈任务默认拆成：后端 / 前端 / 联调验收 三段
- 大任务必须写明锁定文件范围与验证路径
- 一次会话尽量避免超过 3 个核心文件的无计划大改

## 2. 架构一致性规则
- 所有核心模块必须有单一事实来源
- 新逻辑优先复用已有抽象，不要平行复制
- 鉴权、计费、导出、同步、状态机类逻辑禁止到处散落

## 3. 测试与日志规则
- 核心链路必须留可复现验证命令
- 失败日志必须能指向模块与函数
- 不允许空异常吞错，不允许仅打印“失败了”

## 4. 文档同步规则
- 架构变更后同步 `architecture.md`
- 接口变更后同步 `interfaces.md`
- 重大取舍后同步 `decisionLog.md`
- 债务与未完成项同步 `backlog.md`
